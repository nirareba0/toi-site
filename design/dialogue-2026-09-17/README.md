# Miacis 問いコーナー — 対話と多角的視点 プロトタイプ (2026-09-17)

山梨県韮崎市 青少年育成プラザ Miacis（ミアキス）の館内にある紙の「問いコーナー」をWebに広げるローカル動作プロトタイプです。
本プロトタイプは白・薄青の親しみやすい掲示板デザインを基調とし、問いの固有価値（哲学的な対話・多角的な視点の獲得）を前面に押し出した改訂版です。

---

## 起動方法

外部通信・外部フォントダウンロード・ビルドツール・外部依存パッケージは一切不要です。
標準のPythonローカルサーバーで起動できます。

```bash
cd design/dialogue-2026-09-17
python3 -m http.server 8771 --bind 127.0.0.1
# ポート 8771 が既に使用中の場合は代替ポート 8781 を使用してください:
# python3 -m http.server 8781 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:8771/`（または `http://127.0.0.1:8781/`）を開いてください。

## テストの実行

```bash

# ドメインロジック・バリデーション・状態遷移テスト (全18件)
node --test tests/core.test.mjs
```

### テスト範囲 (18項目 PASS)
1. **空白のみの投稿拒否**: 空文字や空白文字（改行・タブ等）のみの投稿を確実に拒絶。
2. **文字数カウントと境界テスト**: `Intl.Segmenter` による書記素クラスタ判定（結合絵文字・国旗を1文字カウント）と500文字上限境界検証。
3. **文字数カウントフォールバック**: `Intl.Segmenter` 非対応環境でも例外を出さずに `Array.from` によるフォールバック動作を検証。
4. **一文・非疑問文の許容**: 疑問形に限らず、日常のつぶやきや一文だけの問いも正しく受理。
5. **ヒントの非侵入性**: 書き出しチップ（なんでだろう／もしも／ちょっとモヤモヤ）選択時に、ユーザーが入力中の下書きが自動上書き・改変されないことの検証。
6. **公開範囲（安全境界）**: 投稿直後（`pending`）の問いが公開一覧（`getPublicQuestions`）に露出しないことの検証。
7. **承認・返信フロー**: スタッフ承認（`waiting`）を経て初めて公開され、大人の返信が可能になる状態遷移の検証。
8. **不正状態遷移の拒否**: 承認済み投稿への再承認、存在しない投稿への返信、取り下げ済み投稿への返信の拒絶。
9. **取り下げの即時反映**: 取り下げ操作によって即座に公開一覧から除外されること、および二重取り下げの防止。
10. **二重送信ガード**: 送信成功時に下書きがクリアされ、同じ下書きが重複して連続送信されないことの検証。
11. **スポットライト安全性**: 「別の問いをひらく」が承認済みサンプルのみを巡回し、未承認のユーザー投稿を一切含まないことの検証。
12. **公開詳細ガード (`getPublicQuestionById`)**: 公開承認済み（`waiting`/`answered`）のみ閲覧可能とし、確認中（`pending`）や取り下げ済み（`withdrawn`）の直接アクセスを拒絶することの検証。
13. **二重送信ガード詳細**: 下書き消費後の再呼び出しで2件目の投稿が作成されないことの検証。
14. **未読バッジ回帰検証**: スタッフ承認（`waiting`）のみでは未読バッジをインクリメントせず、実際の大人からの返信（`answered`）がついたときのみカウントすることの検証。
15. **ルーター解決 (`resolveRoute`)**: スキップリンク（`#main-content`）で404にならず `skip` 判定され現在の画面が保たれることの検証。
16. **受付画面ガード (`getReceiptQuestion`)**: 直前に送信したユーザー投稿のみ受け付け画面を表示し、サンプル投稿や他IDの直接アクセスを拒絶することの検証。
17. **表示用の切り詰め (`truncateForDisplay`)**: 取り下げダイアログやデモ操作の選択肢で本文を短く出すとき、結合絵文字・国旗を書記素クラスタ単位で切り、孤立サロゲート（文字化け）を作らないことの検証。
18. **ページ内アンカーのルーティング**: 「まずは読んでみる」（`#question-list-title`）やスキップリンクを新しいタブで開く・URLで直接指定する経路でも404にならず、`skip` として解決されることの検証。

## 画面構成と主要ハッシュルート

| ルート | 画面名 | 役割・特徴 |
|---|---|---|
| `#home` | ホーム（みんなの問い） | 見出し「問いは、世界の見方をふやす。」、コンパクトヒーロー部（390x844で1件目の問いが初期表示される高さ設計）、トピックフィルター（すべて/暮らし/自分/もしも）、「別の問いをひらく」アクション |
| `#ask` | 問いを書く | 見出し「問いを書く」、補助文「まとまっていなくても大丈夫。」、助言「一文でも送れます。」、500文字リアルタイムカウント、書き出しヒントチップ（枠外表示） |
| `#ask/confirm` | 内容を確認する | 公開時の紙片プレビュー、届く相手の明示文「公開されると、このサイトを見る人が読めます。スタッフの確認前は公開されません。」、注意事項確認チェック、下書き保持による「直す」導線 |
| `#receipt/:id` | 受付完了 | 「問いを受け付けました」「スタッフが確認中です」「まだ公開されていません」、体験版明記、紙片の収まりアニメーション（prefers-reduced-motion対応） |
| `#inbox` | 自分への返事 | 自分の投稿ステータス（確認中・公開中返事待ち・返事あり・取り下げ済み）確認、未読バッジ連携、取り下げ確認モーダルダイアログ、デモ操作パネル（承認・返信シミュレータ） |
| `#question/:id` | 問い詳細 | 問いの紙片表示、大人サポーターによる並列・等幅の複数視点返信カード（深掘りネストなし）、閲覧時の既読更新 |
| `#about` | この場所について | Miacis 問いコーナーの趣旨、哲学的対話と視点を広げる価値の説明 |

## 体験フロー（3画面の基本ループ + スタッフシミュレーション）

1. **問いの作成と確認**:
   - ホームの「問いを書く」を押す → `#ask`
   - 本文を入力（必要に応じて書き出しチップを参照、一文だけでも可）
   - 「内容を確認する」を押す → `#ask/confirm`
   - 公開相手と注意事項を確認し「問いを送る（デモ）」を押す
2. **受付と確認中表示**:
   - 受付完了画面 `#receipt/:id` に遷移
   - 「スタッフが確認中です」「まだ公開されていません」が表示され、紙片が静かに収まる
   - 「自分への返事を見に行く」を押す → `#inbox`
3. **承認と大人の返信（デモ操作ループ）**:
   - インボックス下部の「スタッフ確認のシミュレーション（デモ操作）」を開く
   - 「承認して公開する」を実行 → 問いが「公開中・返事待ち」になり、ホーム（`#home`）のみんなの問い一覧に公開される
   - 「返事を投稿する（デモ）」を実行 → 大人サポーターからの返信が追加され、ステータスが「返事が届きました」に更新
   - 「返事を読む」から詳細画面 `#question/:id` を開き、複数の大人視点の返信を閲覧
   - 閲覧によってインボックスの未読バッジがクリアされる

## 本プロトタイプの境界（スコープ外事項）

- **永続化**: 入力データはブラウザタブのメモリ内（JavaScriptオブジェクト）のみに保持され、再読み込みで初期シード状態にリセットされます。
- **認証**: 本物のユーザー認証およびスタッフ認証は含まれません。スタッフの承認・返信操作はデモ用シミュレータとして提供されています。
- **個人情報・実データ**: 実利用者の投稿や実名は一切含まれておらず、すべて架空のサンプルデータです。
